# henge

## What goes where

Follow Takuto Wada's (t-wada) split:

- Code says How
- Test code says What
- Commit messages say Why
- Code comments say Why not

Comments do not repeat what the code already shows (what it does, how it does it). They state only why another approach was not chosen, or an assumption that breaks things if removed. Documentation sticks to decisions and usage, and does not copy what the code is the source of truth for, such as limits or lists of variables. Write one test per behavior, and do not add tests that check the same thing.

## Public repository

This repository is public. Do not write the names of partners or customers, Slack channel names or IDs, or internal naming conventions in code, tests, documentation, commits or PRs.

## Language

Documentation, code comments and prompts are in English.
